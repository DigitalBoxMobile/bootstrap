# Контракт клиента: bootstrap-манифест

Документ для команд iOS и Android. Реализация должна быть возможна без чтения Python-кода репозитория;
референс — `bootstrap/contract.py`, проверка реализации — `testdata/` (`testdata/README.md`).
Обоснования решений — `docs/adr/0001-signed-bootstrap-manifests.md`.

## Что получает клиент

Файл `<env>.jws` с одного из URL `mirrors` (для первого запроса — URL, зашитые в сборку). Это JWS в
**General JSON Serialization** (единственная допустимая форма, даже при одной подписи):

```json
{"payload":"<b64url>","signatures":[{"protected":"<b64url>","signature":"<b64url>"}]}
```

- base64url — RFC 4648 §5, без паддинга (`=` недопустим), алфавит `A-Za-z0-9_-`.
- `payload` — UTF-8 JSON манифеста. `protected` декодируется в JSON-объект
  `{"alg":"EdDSA","kid":"<kid>"}`. `signature` — 64 байта Ed25519 (RFC 8032, RFC 8037).
- Подписываемые байты: ASCII-строка `protected + "." + payload` (оба — в виде base64url-текста, как в файле).
- Файл заканчивается `\n`; размер ≤ 3584 байт гарантирует публикация, клиент размер не проверяет.
- Другие формы (compact, flattened, незащищённый `header`) не поддерживаются.

## Вход проверки

- байты файла;
- `env` сборки: `production` или `staging`;
- доверенные ключи этого `env`, встроенные в сборку: набор Ed25519 JWK `{kty:"OKP", crv:"Ed25519", x, kid}`.
  `kid` соответствует `^(prod|stage)-[0-9]{4}[a-z]$`; префикс `prod` — `production`, `stage` — `staging`.
  Клиент production не доверяет ключам `stage-*` и наоборот;
- `stored_version` — версия последнего принятого манифеста (`0`, если нет);
- текущее время — только для флага `expired`.

## Проверки по порядку

Первый провал прекращает проверку и даёт код отказа.

| # | Проверка | Код |
| --- | --- | --- |
| 1 | Байты — JSON-объект с `payload` (строка) и `signatures` (непустой массив объектов со строками `protected` и `signature`); все три base64url-значения декодируются | `malformed` |
| 2 | Для каждой подписи: protected header — JSON-объект с `alg == "EdDSA"`, строковым `kid`, без поля `crit`; иначе подпись пропускается (не ошибка). Остальные поля заголовка игнорируются | — |
| 3 | Ни у одной подписи (из оставшихся) `kid` не входит в доверенный набор | `unknown_key` |
| 4 | Ни одна подпись с доверенным `kid` не проходит Ed25519-проверку над `ASCII(protected + "." + payload)` | `bad_signature` |
| 5 | Payload — UTF-8 JSON-объект; `schema` — целое число (не булево, не строка) | `malformed` |
| 6 | `schema != 1` | `unknown_schema` |
| 7 | Структура не соответствует таблице полей v1 (ниже) | `invalid_manifest` |
| 8 | `env` манифеста не равен `env` сборки | `env_mismatch` |
| 9 | `version < stored_version` | `rollback` |

Принято — манифест возвращается как есть. Порог подписей — 1: достаточно одной верной подписи доверенного
ключа; неверные, чужие и пропущенные подписи рядом с верной не мешают (так работает ротация ключей).
Равная версия не откат: `version == stored_version` принимается.

### Срок: мягкий

`expired = now >= expires_at`. Просроченный манифест **принимается**; флаг нужен клиенту, чтобы чаще
обновляться и показать пользователю уведомление, но не отказаться от работы.

## Поля манифеста v1

| Поле | Обязательно | Правило |
| --- | --- | --- |
| `schema` | да | число `1` |
| `env` | да | `production` или `staging` |
| `version` | да | целое ≥ 1 |
| `issued_at`, `expires_at` | да | `YYYY-MM-DDTHH:MM:SSZ` (UTC), реальная дата |
| `base_domains` | да | массив ≥ 1 уникальных hostname в нижнем регистре без схемы, порта и точки в конце |
| `health_path` | да | строка, начинается с `/` |
| `mirrors` | да | массив ≥ 1 уникальных строк, начинающихся с `https://` |
| `policy` | да | объект; `connect_timeout_ms`, `probe_interval_s`, `refresh_interval_s` — целые > 0, все обязательны |
| `min_app_version` | нет | объект `{ios, android}`, строки |
| `notice` | нет | объект `{ru, en}`, строки |

Целое — JSON-число без дробной части и без экспоненты: `3.0`, `3e0` и `1E2` целыми не считаются, манифест с такими
значениями (`version`, поля `policy`) отклоняется как `invalid_manifest`; булево значение тоже не целое.

Неизвестные поля на верхнем уровне и в `policy` игнорируются (расширения совместимы с v1). Машинная схема —
`schema/manifest.v1.json` (JSON Schema Draft 2020-12), её ограничения и таблица выше совпадают.
Проверка `expires_at > issued_at` — дело публикации, клиент её не делает.

## Выбор домена

Домен из `base_domains` живой, если на `https://<api-host>.<domain><health_path>` за `connect_timeout_ms`
установлено TLS-соединение и получен **любой HTTP-ответ**; статус не учитывается. Так проверяется весь путь
DNS → TLS → Traefik. Опрос — каждые `probe_interval_s`, обновление манифеста — каждые `refresh_interval_s`
(и при провале всех известных доменов).

- Активный базовый домен один на приложение: домены пробуются по порядку `base_domains`, первый живой запоминается,
  все известные приложению поддомены строятся от него. Раз в `probe_interval_s` основной домен пробуется снова —
  возврат на него автоматический.
- Абсолютные URL из ответов backend (картинки, файлы, ссылки оплаты, websocket): если хост оканчивается на любой
  из `base_domains`, базовый домен заменяется на активный.
- Deep links, OAuth redirect и платёжные SDK в манифесте не участвуют — у них внешние регистрации.

## Получение и кеш

```
cached   = verify(load_cache()) or verify(embedded)
use(cached)                                    # приложение работает сразу
if cache_age > refresh_interval_s or last API error was DNS/connect:
    results = hedged_fetch(cached.mirrors ∪ embedded.mirrors, total_timeout = 5 s, stagger = 300 ms)
    best = max(version, [m for m in results if accepted(m)])
    if best and best.version >= cached.version: save(best); use(best)
```

- Встроенный в сборку манифест — такой же JWS, проверяется тем же кодом; отдельного пути «нулевого дня» нет.
- Кеш перепроверяется при каждой загрузке (устройство может быть рутовано). Версия и кеш — в Keychain (iOS)
  или EncryptedSharedPreferences (Android).
- Зеркала опрашиваются параллельно со ступенькой 300 мс; берётся **максимальная** версия среди принятых — отстающее
  и враждебно застывшее зеркало обрабатываются одинаково. Повторные запросы — с `If-None-Match`.
- Любая ошибка DNS или соединения в основном HTTP-клиенте — триггер немедленного обновления манифеста и перевыбора домена.
- Часы устройства влияют только на флаг `expired`.

Ed25519: iOS — CryptoKit `Curve25519.Signing` (iOS 13+); Android — Tink или BouncyCastle
(`java.security.Signature("Ed25519")` есть только на новых API-уровнях).

## Проверка реализации

Прогоните все векторы из `testdata/vectors.json` (формат — `testdata/README.md`): результат обязан совпасть
с `expect` для каждого, включая точный код отказа. Векторы можно проверить и «сырым» Ed25519 без JOSE-библиотеки
(`tests/test_vectors_raw.py` — пример на `cryptography`): JOSE-библиотека не обязательна.
